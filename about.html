About me

I’m an electrical engineering student working on digital hardware: processors, FPGA architectures, and the software used to simulate and implement them.

Starting with a processor

My projects have grown out of specific technical questions. For the 16-bit CPU, the question was how to turn an instruction set into a working processor. I designed a 12-instruction ISA, wrote a Python assembler, and implemented a five-stage pipeline in SystemVerilog. Forwarding, load-use stalls, and branch flushing became concrete problems to solve rather than just names in an architecture diagram.

Getting the CPU onto an FPGA added another set of problems. A memory address that was too wide caused synthesis to attempt an enormous multiplexer. A simulation-only initialization block left memory uninitialized on hardware. Working through those failures was part of getting a Fibonacci program running on a Tang Nano 9K, with its output shown on two seven-segment displays.

That project gave me an interest in the whole path from a design decision to observable behavior. I wanted to understand both the processor’s structure and how to check that it was doing what I intended.

Following the question into software

The CPU then became the test circuit for my CUDA logic simulator. I used Yosys to turn it into a netlist of 20,170 gates and 8,676 flip-flops, organized the gates by their dependencies, and built CPU and GPU execution paths. The first GPU implementation spent too much time launching kernels. Moving the simulation into one persistent kernel reduced GPU runtime by 4.7 times and brought it to about twice the speed of the CPU at 100,000 cycles.

Performance was only one part of that work. Wire-name collisions in the flattened netlist caused nondeterministic GPU results. After fixing the naming step, I compared the final state of every signal between the CPU and GPU. That experience reinforced the need to establish correctness before treating a faster runtime as a useful result.

Working in larger design flows

My research work extends that interest to 3D FPGAs. I prototyped a configurable logic block with ten LUTs split across two die layers, changing VTR’s architecture parsing and placement and OpenFPGA’s RTL generation. I also took a single-die baseline through synthesis and place-and-route in OpenROAD, checking the RTL and resulting netlists with functional simulation.

On a student ASIC design team, I have worked on an RV32I-subset processor, class-based verification, and a Sky130 physical-design flow. That work includes coverage analysis, SRAM macro placement, timing analysis, clock gating, and DRC/LVS debugging. It has given me practice reading evidence from several tools and tracing a failure back to the design or constraints that produced it.

Beyond the processor

I also work on embedded systems. On a four-person posture-wearable project, I owned the ESP32 hardware and firmware: bringing up a BNO055 motion sensor, calibrating an upright baseline, filtering brief movements, and sending posture data over BLE. The project required a clear interface between firmware and the web dashboard my teammates built.

An earlier IT internship involved migrating approximately twenty workstations to Windows 11 and configuring hardware firewalls. Across these experiences, the work I want to keep doing is hands-on and specific: build a system, measure its behavior, and use those results to decide what to improve next.
